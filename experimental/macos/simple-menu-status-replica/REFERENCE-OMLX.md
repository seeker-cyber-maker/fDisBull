# oMLX comparison (31 October 2026)

The user pointed to [jundot/omlx](https://github.com/jundot/omlx), an Apache-2.0 native macOS project with a similar system-stats menu. This is a source comparison, not evidence about Simple Menu STATUS's internal implementation.

- [SystemStatsSampler.swift](https://github.com/jundot/omlx/blob/6c352183616af1ffbca6c1c0b2a103e2667c12b5/apps/omlx-mac/Sources/Menubar/SystemStatsSampler.swift#L260-L289) reads `HOST_VM_INFO64` and `host_page_size`, then estimates displayed used memory as active + wired + compressor pages. The replica's headline uses the same accounting principle.
- [psutil_compat.py](https://github.com/jundot/omlx/blob/96361a5883fcf50f9eb7f22a9f2cecfe76bb62fb/omlx/utils/psutil_compat.py#L1-L8) documents a macOS 27 VM-stat compatibility issue. Its [available-memory calculation](https://github.com/jundot/omlx/blob/96361a5883fcf50f9eb7f22a9f2cecfe76bb62fb/omlx/utils/psutil_compat.py#L146-L170) includes free and inactive pages. The replica uses that reclaimable-aware idea to seed the emoji until macOS delivers a memory-pressure event.
- [SystemStatsPanels.swift](https://github.com/jundot/omlx/blob/6c352183616af1ffbca6c1c0b2a103e2667c12b5/apps/omlx-mac/Sources/Menubar/SystemStatsPanels.swift#L141-L214) demonstrates a compact 270-point memory panel with a colored bar and detailed legend. The Simple Menu STATUS screenshots, rather than oMLX, remain the visual target for this replica.
- [SystemMenubarItemsController.swift](https://github.com/jundot/omlx/blob/6c352183616af1ffbca6c1c0b2a103e2667c12b5/apps/omlx-mac/Sources/Menubar/SystemMenubarItemsController.swift#L40-L78) skips status-image redraws when its quantized visual signature is unchanged. Its [sampler](https://github.com/jundot/omlx/blob/6c352183616af1ffbca6c1c0b2a103e2667c12b5/apps/omlx-mac/Sources/Menubar/SystemStatsSampler.swift#L1-L12) is polled only while its system-stats submenu is open. Those patterns are useful for later performance tuning.

oMLX does not supply Simple Menu STATUS's emoji glyphs, thresholds, or bug cause. A displayed used-memory ratio and an OS memory-pressure state answer different questions; the replica keeps them separate. On this Mac, `vm_stat` showed few literally free pages while `memory_pressure -Q` reported 70% system-wide memory free. That supports treating reclaimable pages differently from literal free pages, but does not establish the Store app's code path.
