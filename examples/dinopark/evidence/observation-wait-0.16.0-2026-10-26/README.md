# DinoPark observation-wait evidence

Generated by `examples/dinopark/verify_wait.py` with the real DOSBox backend and
unchanged DinoPark inputs. Only selected evidence is retained here. Game inputs,
native states and project databases remain in the private validation directory.

- The saved price-byte wait matched initially and executed **zero** guest runs.
- The false predicate returned `guest_budget`, retained its last values and
  exported a genuine diagnostic frame. The request was 40 guest milliseconds;
  the first completed slice measured 130, and the 90 ms overshoot is explicit.
  This is a failed bounded observation, never a claim of success within 40 ms.
- The original street checkpoint was restored, then the matched concession
  experiment still observed the baseline 7,500 versus altered 5,000 lookup.
  Its execution breakpoint, eight read-watch bytes, once hook/hit count and layer
  stack were restored. Processes were reaped and all **192** original and mounted
  game files remained unchanged.
- A separate bounded static pass described 29 known services among 50 inspected
  DOS/BIOS interrupt sites, including open/create/read/write/close operations.
  That pass remained partial with pending work; it is not full coverage.
- No qualified Microsoft runtime identity was found in this bounded DinoPark
  slice. The first bundled catalog does not establish Borland runtime coverage.

This is **not** a replay of Pro's E32 cancellation investigation and does not
prove UI readiness from the price bytes, a camera value or a fresh frame. Known
builder/cancellation return breakpoints remain the caller's synchronization
instruments. The new wait supplies a generic bounded observation loop.

`wait-diagnostic-grid8.png` is derived from the stored authentic diagnostic frame.
The original 45-file driver evidence was checked against its untouched manifest;
`MANIFEST.json` links these selected files to that manifest and the raw frame hash.
The static render and grid are separate derived evidence. The two raw traces
retain their backend's pending-last-fetch semantics as recorded in the comparison.
