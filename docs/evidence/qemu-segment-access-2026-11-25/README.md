# Protected-mode segment access candidate

This is a bounded local comparison of an incremental QEMU 10.0.13 TCG patch against the frozen DOSBox-X binary. The final QEMU executable is identified by SHA-256 in [verification.json](verification.json). Private COM run images, checkpoint payloads, executables and JUnit XML remain outside Git.

The earlier QEMU candidate completed an authored `REP MOVSB` across a 64 KiB DS limit without a fault; DOSBox-X entered the guest #GP handler after copying `AB` and retried the remaining `CD`. An independent scalar `MOV` probe showed the same difference for an access starting at `DS:0x10000`. The new candidate checks the actual segment-relative byte range before the selected string and integer scalar accesses. It preserves the REP iteration count, indices, copied prefix and fault frame through the handler and a fresh-session QEMU checkpoint restore. A dword read beginning at `0xFFFE` also faults before the read and succeeds after the handler widens DS.

Two further authored probes remain **compatibility differences**. On `LOCK CMPXCHG` spanning the same DS limit, the patched QEMU enters #GP before the atomic update; the frozen DOSBox-X completes the update without entering the handler. With null DS and an offset-zero read, QEMU enters #GP; DOSBox-X reads through the null selector and completes. Both outcomes are asserted by the native test, and neither is recorded as 1:1 parity. The [AMD64 architecture manual](https://docs.amd.com/v/u/en-US/24594_3.37) identifies an out-of-limit data reference and a null data-segment reference as #GP causes.

The selected local native batch passed 29 tests with no skips on the exact final QEMU binary. This includes paired REP/scalar probes, the two recorded reference differences, QEMU cold restore at the REP fault handler, earlier REP boundaries, and selected LE, fault-frame, history and protected/V86 checkpoint regressions. These tests evaluate this candidate; they do not qualify general x86 behavior, the trace-events workgroup, target campaigns or a DOSBox-X default switch. The patch covers selected string and integer scalar paths. Access rights, vector, implicit stack and other specialized memory paths still need dedicated qualification. No CI, release, installation or DotBox change occurred.
