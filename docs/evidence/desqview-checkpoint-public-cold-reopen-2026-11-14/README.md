# Checkpoint-build public cold reopen and export

The public cold-reopen gate passed on frozen runtime `daab62e573727eb2df64609cc9e0fac204ea16cf`, using an isolated copy of the closed original DESQview checkpoint trial. This extends the previous historical `fdbda4c9` public check to the actual checkpoint build and its restored epoch.

Two controlled Project reopens verified 348 alias queries, 29 historical views and 28 explicit restore-phase queries at journal sequences 4, 8, 9, 10, 11, 13 and 14. Complete interval and source-proof descriptor matches came from independent pristine SQLite/CAS values. The queries preserved the new epoch, task UUID, process episode and proof identities. Restored generation zero and `creation_observed=false` remain source-observed, with native creation unknown; a reused native handle does not continue the old authority. Intermediate publication states are historical journal boundaries rather than separately observed native stops.

Both one-shot JSON and retained `serve` passed all 47 selected cases, including three typed pre-incarnation refusals per path. A further 23 named CLI checks passed: 193 retained replies in total, with strict JSON scalar types and explicit address formatting. Both paths exported the entire selected set of 17 detailed errors, nine certificates, nine snapshots and one checkpoint: 72 exact exports. The 17 older errors remain durable even though the restored tracker counter resets to zero.

The 11,927,552-byte checkpoint exported byte-for-byte through Project and both JSON paths (SHA-256 `cbe045dbd83a64cc13f6504cb261bcecc5ae3c18131041ca3782ca2c3ac40ae0`). Its public metadata retains `runtime_tracking_controls_serialized:false`. A reply truncated at 4,096 bytes was recovered as the exact 10,127-byte saved completed reply without replaying its request; unknown execution completion/status remain null. No positive semantic ambiguity was observed.

Canonical and cloned DB/CAS, all 327 object entries per store, all 709 runtime payload files and the original image/native-tool/firmware pins remain unchanged. Both actual Project store roots were the isolated clone. The controller and retained server exited and were absent; no WAL/SHM remains. Original executables were untouched. Both executed controls were frozen before their first execution and stayed unchanged. Independent review reconstructed all 47 cases from pristine SQL/CAS and checked all 193 actual replies and exact exports, finding no blocking issue.

This is cold public history/query/export qualification after the already-observed real restore. It does not execute another guest or native restore, infer continuous lifetime, establish whole-task RAM authority, or add changed-RAM undo evidence. The native trial's selected 734-byte RAM window had zero intervening changed bytes. Broader checkpoint compatibility and DOSBox replacement remain separate. No CI, native rebuild, production change, merge, release or activation occurred.
