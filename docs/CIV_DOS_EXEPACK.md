Slice ID: `CIV-EXEPACK-001`

Status: **proven for the pinned DOS 474.05/475.05 byte identity; static city
coverage remains bounded**.

## Input and output identity

The input is the civd verified build:

```text
source: /Volumes/CODEX/Codex_Projects/Civd-intake/verified-builds/47405/CIV.EXE
bytes:  305030
sha256: 22de2748e3089793644c7e501e2a95b553010ddec34a7ff42f4395cf779c9c2a
```

`examples/civ/civ_exepack.py` is a clean-room, bounded EXEPACK decoder. It:

1. validates the MZ and `RB` EXEPACK headers;
2. reverses and decodes the B0/B2 backward command stream;
3. reconstructs the 16 relocation buckets in their stored order;
4. rebuilds the root MZ header and keeps the original root entry/stack;
5. appends the bytes after the packed file's declared size unchanged.

The generated comparison artifact is:

```text
bytes:  340791
sha256: aa63aa396cfa62519b131ee6c0a231bed02bb9aefce26b955608b5815a569e57
```

That is the expected `CIV_UNP.EXE` identity in the Civ64 DOS records. The
comparison was made against the independent UNP 4.12 oracle in a temporary
workspace; neither the oracle binary nor proprietary game bytes are added to
this repository.

The MZ `e_cp`/`e_cblp` fields describe the rebuilt root load module, not the
physical file including Civ's 23 overlays. The decoder also adjusts
`e_minalloc` by the paragraph growth from the packed root plus EXEPACK stub to
the decoded destination. These details are required for the generated bytes to
match the published `CIV_UNP.EXE` hash; a size-only unpacker is insufficient.

| fDisBull image base | linear `0x10000` (`load_segment=0x1000`) | fDisBull MZ loader |

Civ64's `R:ssss:oooo` addresses are relative to the root load module. Therefore
`R:0D12:0045` has load-module offset `0x0D165` and is queried in fDisBull as
runtime `1D12:0045` (`0x1D165`). Supplying the literal `0D12:0045` addresses a
non-mapped runtime region and is not equivalent.
