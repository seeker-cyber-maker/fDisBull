## Architecture

The complete adaptation uses its existing world JSON and deterministic `Game` runner through `text/bridge.py`. It supports exact commands, scene travel, inventory, hints, undo, flashback inventory stashes and portable saves. A conversational model maps intent to known actions and narrates only confirmed results. No cloud API or browser is required for that runner.

Recovered original behavior uses fDisBull's existing typed `fdisbull-il-1` representation. The new catalog exposes six selected branches. Its local JSONL interface returns source text references and only the retained effects that the translation actually covers.

`fast_pipeline/` adds the new poster lowering and the existing PR18 `fdisbull-il-scene-1` projection. Discovery proceeds outline → typed source obligations → executable shared IL → playable Z projection. All 51 broad descriptions refuse execution until independently lowered; seven selected models can execute. The PR18 source is pinned separately from installed 0.22. Role-copy timing is distinct from source lowering, and source-model state is distinct from current native state.

The original game runs in the supplied DOSBox backend. `native_progress/bilge_native.py` exposes a guided command at each qualified route boundary and creates real `fdisbull-scene-1` action documents. VM memory is read to establish identity, geometry and effects; all state changes come from ordinary guest input. Every route action is accompanied by source and runtime evidence.

These are separate authorities. The authored world is not silently substituted when a native action fails. The bounded branch model does not pretend to be a complete native interpreter.

## Decisions

- Keep the existing full text game intact and record original-versus-adaptation differences separately. The earlier adaptation's convenient puzzle descriptions do not prove native interaction order.
- Use existing fDisBull formats. The route manifest schedules the observed steps; it is not a new universal UIL dialect.
- Preserve the canonical bilge packet's 18 targets and 31 rules; combine it with the new hold packet's five targets and twenty rules through recorded identities and source conditions.
- Accept conditional source claims separately from reachability, native readiness, committed effects and persistence. Reuse existing qualification instead of replaying an unchanged route for each pure lowering.
- Keep unresolved calls and unsupported opcodes explicit. Source descriptions remain blocked; a retained-output projection is not a whole-handler implementation.
- Mark current Z packages as investigator interfaces. Player-knowledge parity is unqualified because bilge context IDs expose some hidden state.
- Bind object identity to release, script, camera, presentation, state and selected item. The same screen coordinates may represent a different live target after a visit.
- Separate displayed text, committed puzzle effects and input readiness. First-water and pump-work projections explicitly omit some native control/presentation behavior.
- Require current context tokens on native execute. Ambiguous delivery halts the route; it never triggers an automatic repeated click.
- Keep the native route's portability claim bounded to its calibrated presentations. Live coordinate translation is implemented; arbitrary popup placements have not been fully qualified.
- Preserve mutable mount files alongside saves and restore them explicitly. The game changed `cat.inf` on close, and native checkpoints intentionally do not restore disk bytes.

## Research

**Minimum proof budget:** pin resource/entry and semantic profile, close the relevant dependency slice, establish a nonvacuous guard and effect agreement, and state the result boundary. Source evidence supports conditional acceptance; formal whole-program equivalence is not claimed. Independent review checked 23 final identities without rerunning the pipeline.

**Fresh poster:** camera0/empty hands selects text31 at counter0, text32 at1, text33 otherwise, then increments signed byte12637 modulo256. Source geometry disables the target at−1, so handler-domain testing is separate from callable scene visibility. The pinned ScummVM signed-read/unsigned-write chain supports the chosen profile; original DOS overflow was not newly observed.

**Speed:** six official Gob decodes took18.57ms in total; primary AST/dispatch/hotspot checks took2.50ms; source packet build47.47ms; whole supplied-container inventory172.47ms. Final pipeline rebuild162.736ms includes44.452ms for poster cases and71.743ms for candidate-player checks. Warm bilge lowering is2.832ms, new poster lowering0.811ms after its mapper was authored, and role copy1.432ms. These are separate machine measurements, not cold analyst recovery time.

**C/ASM:** the authored public microbenchmark found supplied-C parsing cheaper, while ASM→C→IL was slower than direct ASM→IL. It covers only straight-line uint16 register examples. The original EXE entry analysis reached16 instructions/29bytes at a copy/far-return boundary, so it cannot provide a matched whole-game comparison. Direct Gob decoding is the useful scene source layer.

**Entry and revisit:** first descent uses hold camera 1/raw target 11 with lamp item 1 selected. Re-entry uses raw target 21 at the same rectangle with empty hands. Visit count reaches two without resetting drained water, recovered corkscrew or consumed oil.

**Oil:** the original interaction is cask → cask detail → bottle. Picking up oil selects item 14. At the pump, applying it to the actual handle consumes item 14 and sets the oil flag; opening the pump close-up alone does not apply it.

**Water timing:** the first response text is visible before the checked-water flag commits. The repeat response uses a separate branch. A neutral click following that response is retained as an observed UI gesture with preservation checks, not a fabricated puzzle transition.

**Pump timing:** the drain flag commits before the final message is dismissed. Closing the inset is a separate native effect omitted from the bounded UIL projection; `$subview` passthrough is therefore excluded from native output parity.

**Geometry timing:** a corkscrew target can be partially registered despite idle animation fields. A script name can also change before the destination's geometry has replaced the old scene's table. These observations justify complete geometry and presentation checks.

The source decoder was built from official ScummVM Tools commit `16f178fbb0e03eb122029050dfd3189451a5c6f2`. EMAM1018 and MENU decode fully. The full hold decode remains partial because of unsupported opcode 0.4; the selected bounded hold routines have explicit successful receipts. `bilge_source/SOURCE_REPORT.md` contains the exact commands, resource identities and offsets.

## Questions

No user decision is needed for the delivered slice. The remaining engineering questions concern reusable helper summaries, safe claim-cache integration, public player-knowledge filtering, scene streaming beyond the candidate's 32-program package limit and first native qualification for the newly recovered hold targets. The requirements PR states concrete acceptance checks for each seam.

One recovered-session copy failed an integrity check. The code had a definite SQLite connection-lifetime defect: context-managed transactions had been mistaken for closed connections. The continuation helpers now explicitly close backup connections before opening the target project. A fresh source import was used for successful new native work. The precise cause of the earlier malformed database is unresolved; the failed database is excluded from the deliverable and its diagnosis is retained. No engine-level fix is claimed.
