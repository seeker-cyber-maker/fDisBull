## Reproduction and implementation

The preceding original-game batch stopped at Employment after 10.349091 host
seconds and 2,170 guest milliseconds. One click was accepted and queued. Its
stored frame still showed the street; successful EMPOFF.ACT/PIC reads were
loader evidence, not a destination witness. That provider remains held.

The shared business-entry factory now gives Employment, Dino Diner and General
Store the same finite 40-second host allowance as DinoMart, retaining the
12,000-millisecond guest bound. Z starts its shared native RPC budget before
request observation and releases it before the separately bounded recovery
status check. This protects native cleanup capacity under instrumentation.

The scene engine retains the original queued input and source observation when
a native postcondition read raises an ordinary exception, as it already did
for explicit scene failures. Successful business clicks also publish a private
receipt before later qualification or rendering. Existing returned scene,
action-name and run facts are preserved rather than overwritten.

Read-only navigation reconciliation now covers all four street businesses.
Authorization remains bound to the original command/action, same provider
session/run, original source revision, named control, before observation and
accepted queued input. It qualifies the requested destination using a fresh
hook-free frame and returns the original action certificate. Failed reads do
not authorize another input.

A missing normal final witness now retains the original business action instead
of returning success without its witness. Matched navigation with matching raw
identity retains its confirmed effect. Foreign identities stay unknown. A
failed reconciliation witness preserves published target scene heads, while
holding the action, so a later read-only retry does not refer to an obsolete
parent revision. The separately observed checkpoint-restore namespace conflict
is not claimed fixed by this narrower change.

## Additional observed friction

- The ordinary land helper can return an unknown outcome in about 2.59 seconds
  after six accepted inputs, with an uncommitted plot-selection frame. This
  setup defect is separate from the Employment deadline. Its provider remains
  retained and was not replayed.
- The private fixture had omitted one resource that legacy saves still bind.
  A useful mismatch response would report bounded missing/extra/hash-different
  names, together with the actual selected input inventory. The current exact
  equality check was honored, not bypassed or weakened.
- Source ready/enabled evidence was initially misattributed to the destination
  outcome. Role-tagged predicate explanations would make that distinction
  easier for an agent. The original contradictory explanation and correction
  remain in private provenance.
- An attempted readback was named `land-committed.png` before its guard passed.
  Artifact names should identify the attempted phase; the validation result
  should carry the commitment claim.

- The successful Store return took about 43.4 seconds and encyclopedia viewing
  about 38.6 seconds. These legacy requests remain outside the new business-entry
  scope. Bounded continuations, progress and per-action guest/calendar deltas
  would make their cost and recovery behavior clearer; failure injection for
  those legacy paths was not performed.
- Lean startup now has a real partial interval rather than an unqualified
  callback absence. Budgeted startup phases and reusable instrumentation profiles
  would avoid treating a fixed 35-second guest wait as guaranteed under a
  15-second instrumented host allowance. The timing sample is not by itself a
  demonstrated backend performance defect.
- Host fixtures must enforce the actual native request schema and propagate the
  product result. Method-name-only stubs missed the address-format defect, and
  a wrapper exit zero initially concealed product failure. The private fixes
  remain outside the tool package; their evidence and limitations are retained.
- The three new CALL/slot witnesses suggest a reusable provenance-bound promotion
  path into analysis xrefs. A published callback address should remain distinct
  from a runtime invocation, and neither should silently become a whole-routine
  proof.
