# Scene content and game-space navigation

An optional scene `content` object has three authored predicates: `requested`, `displayed`, and `ready`. All three are required. A scene observation reports each independently from `scene_matched`; an action requires all three and the selected object's availability. A missing observation is incomplete. Existing scenes without `content` retain their previous behavior. An optional object `outcome_phase` records the author's declared `state`, `interface`, `persistence`, or `unspecified` boundary; it is not independent proof of rendering or persistence.

A scene may also contain `navigation`. This is immutable with the scene revision and bound to the same byte version. Its `space` names a game coordinate system, distinct from native frame pixels. `width` and `height` define its bounds. `actor` has integer `width`, `height`, and an `anchor` offset within its rectangular footprint. `walkable` uses the existing rectangle, polygon, union, intersection and subtraction raster semantics. `colliders` have unique `id`, `area`, and a scene predicate `when`. Optional `anchors` and `portals` carry unique IDs and points; they are descriptive, not teleport operations. `provenance` requires an `extraction_rule`, a nonempty `source_facts` list and `evidence_status`. These are authored claims, not independent verification.

`navigation_check(doc, point, conditions=...)` classifies the full footprint as `clear`, `blocked`, or `unknown`. An overlapping collider with a missing or unknown condition is unknown. `route_first_boundary` samples each integer step between route points and returns the first non-clear result. These are geometric checks, not guarantees of actual movement. `SceneHandle.navigation_check` freshly observes predicates on a paused guest and returns the manifest hash and observation evidence. If the scene is not matched, its classification is unknown.

For each route segment, the checker takes `max(abs(dx), abs(dy))` steps and rounds each interpolated coordinate with Python's ties-to-even rule; it checks the initial point once and each subsequent step, including the endpoint. This is a discrete prediction, not continuous collision detection. Routes are limited to 4,096 supplied points and 65,536 interpolated steps; combined binary masks are limited to 32 MiB. Masks are compiled per call and never cached across revisions or observations.
