# Repeatable recovery for a first-time agent

The bundled `fdisbull-investigate` skill now includes
`references/reconstruction.md`. Retrieve it through `agent-skill` from the
selected runtime; no earlier chat, project history or external manual is needed.
The entry point defines UDL/UIL/UDC, identifies the actual tool environment and
routes recovery/translation/provider changes through the original/model/output
acceptance procedure.

## What the previous guidance covered

The existing proof guidance already distinguished supplied-model proofs from
source fidelity. The installed sweding guide required comparison of each
source/model/implementation edge and then the composed operation. The requested
outcome was broad, but the four concrete PR #50 discrepancies were not choices
left open by an ambiguous task:

- The original suppresses a contribution during disorder; it preserves stock.
- MZ load-module length excludes the header, while declared file end includes it.
- Relocations include a segment as well as an offset.
- Caller mode comes from the reaching value in the ABI slot, not an earlier zero.

Agreement between an authored interpreter and its compiler did not test those
source interpretations. The observed workflow gap was failure to apply that
first comparison, with insufficient discriminating examples and inconsistent
skill snapshots. The available mixed-model session does not establish a
general ranking of models or prove which contextual factor caused the failure.

## Concrete changes

The recipe gives one sequence: select tools and task, pin inputs, qualify
addresses/control flow, define the observable contract, observe the original,
compare UIL, realize/test a target, then compose/persist/handoff. It requires
nonzero retained state, thresholds, signed extremes, wrap/reset/refusal cases
and negative controls where relevant. Unsupported effects, types and domains
remain visible; an agent must not erase them to fit a backend.

The companion receipt example keeps original-to-model, model-to-target and
composed checks separate. It is labeled as an example rather than a tool schema
or automatic execution certificate. Models can still be built as unqualified
candidates; the promotion of a recovery claim is the gated action.

The prior architecture guide for alternative backings is retained, reviewed and
committed into this coherent bundle. Runtime and installed-skill identities must
be recorded separately. Installation uses one reviewed revision and file hashes,
with a backup of the prior snapshot; a live agent may need to reload it.

## Verification and remaining scope

The seven-byte authored fixture in the recipe runs without a game or project.
Its positive test preserves nonzero stock, and its negative test substitutes a
wrong zeroing branch and detects the mismatch. These execute instructions rather
than matching headings or prescribed prose. Native ARM64 probe tests separately
check signed-byte widening, wrap, domain/refusal guards, a wrong implementation,
truncated input and persisted UIL identity.

The new food recipe and its dependency are explicitly allowed in source
archives. PR #50 likewise includes the exact reviewed Civ recipe dependencies,
so packaged source can run its tests. General example and private-data exclusions
remain; no original executable, byte-bearing database, toolchain or native
generated output is published.

The macOS-compatible suite passed 2,250 tests, with 132 skips and two deselected
ELF probes. Parent ELF compiler limitations remain excluded as documented in
the PR. Linux/native CI is a separate gate. Skill structure, every indexed
reference, packaged reads and the first-use execution exercise are checked.
This is reproducible procedural and executable validation, not an empirical
test of every model's ability or an enforcement guarantee for arbitrary agents.
